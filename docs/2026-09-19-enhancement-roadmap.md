# YUAN27.top 网站增强路线图

## 1. 目标与原则

### 1.1 核心目标

把当前已经基本部署完成的 YUAN27.top，从“能访问的个人网站”升级为一个更有记忆点、更好玩、更适合展示个人能力的终端式网站。

目标不是堆功能，而是让访问者在打开网站后产生三个感受：

1. 第一眼觉得有氛围。
2. 能自然探索出你的个人信息、项目、博客和简历。
3. 玩一会儿后愿意继续输入命令、发现隐藏内容。

### 1.2 保留现有架构

继续沿用当前方向：

- 可拖动 Terminal Window 作为主入口和唯一的内容阅读区。
- Desktop Background 作为窗口之外的氛围层与轻量导航层。
- Virtual File System 作为内容组织方式。
- 命令系统作为交互核心。
- 页面内容通过 `ls`、`cat`、`tree`、`cd` 等命令逐步展开。

不建议现在改成传统作品集首页，也不建议引入复杂后台、账号系统或数据库。

### 1.3 双线体验边界：窗口内与桌面背景不混用

网站从这里开始有两条独立但协作的体验线：

| 体验线 | 承担内容 | 用户主要行为 | 不承担的职责 |
| --- | --- | --- | --- |
| 窗口内：Terminal | 个人信息、项目、博客、简历、命令和彩蛋 | 输入、阅读、探索文件系统 | 模拟完整操作系统桌面 |
| 窗口外：Desktop Background | 空间氛围、屏保式互动、快捷入口与状态反馈 | 拖动窗口、轻点图标、观察背景互动 | 重复展示项目详情或替代终端导航 |

两条线的唯一衔接原则是：桌面上的操作只负责“唤起或定位”终端内容。例如点击 `Projects` 图标后，终端置顶并执行等价于 `cd /projects`、`ls` 的引导输出；项目详情仍在终端内阅读。

这样既能让页面更像一个小型桌面环境，也不会形成两套内容系统。

### 1.4 设计原则

- 主次清晰：先提升第一印象和基础探索体验，再加彩蛋和高级互动。
- 克制设计：终端风格要高级、干净、有氛围，不要变成模板化赛博朋克。
- 内容优先：每个命令都应该服务于“展示你是谁、做过什么、会什么”。
- 易维护：新增功能尽量基于现有命令系统和虚拟文件系统扩展。
- 可渐进发布：每一阶段都可以单独上线，不依赖一次性大改。
- 双线分工：窗口内负责内容深度，桌面背景负责氛围、快捷操作和轻量反馈。
- 真实感适度：借用桌面系统的熟悉感，不复制复杂的窗口管理器或操作系统逻辑。

## 2. P0 核心体验：先让网站“像一个完整系统”

P0 是最高优先级。它决定访问者打开网站后的第一印象，也决定后续功能是否有承载感。

### 2.1 启动流程与欢迎界面

新增一个短启动流程，例如：

```text
Initializing YUAN27...
Loading profile modules...
Mounting /about...
Mounting /projects...
Mounting /blog...
Connection established.

Welcome to YUAN27.top
Type "help" to begin.
```

建议：

- 启动动画控制在 2 秒以内。
- 支持跳过，不要影响老用户重复访问。
- 文案保持简洁，不要过度中二。

验收标准：

- 首次进入页面有明确氛围感。
- 用户知道可以输入 `help`。
- 启动过程不会拖慢主要内容展示。

### 2.2 `help` 命令重构

`help` 应该成为用户探索网站的导航入口，而不是简单列一堆命令。

建议按类别展示：

```text
Core
  help        Show available commands
  clear       Clear terminal
  tree        Show site structure

Explore
  ls          List files
  cd          Change directory
  cat         Read file
  open        Open external resource

Profile
  neofetch    Show Yuan's profile summary
  resume      Open resume

Fun
  coffee      Boost productivity
  sudo        Try privileged actions
```

验收标准：

- 新用户能从 `help` 理解下一步该做什么。
- 命令数量不吓人，按类别清楚展示。
- 每个命令都有一句简短说明。

### 2.3 `neofetch` 个人信息展示

这是最推荐优先实现的展示功能。它非常符合终端主题，也能快速说明你是谁。

示例内容：

```text
YUAN27
────────────────────────
Host      yuan27.top
Role      AI / Backend Developer
School    HUST
Focus     Agent · RAG · Backend
Projects  12
Blog      24 posts
Status    Building quietly
```

可以左侧放简洁 ASCII 标识，右侧放信息。

验收标准：

- 输入 `neofetch` 后能一眼看到个人定位。
- 信息真实、简洁、不过度夸张。
- 在移动端也不会排版错乱。

### 2.4 Virtual File System 内容梳理

先把网站内容整理成清晰目录，再做复杂互动。

推荐结构：

```text
/
├── about
│   ├── bio.md
│   ├── education.md
│   └── skills.md
├── projects
│   ├── agent
│   ├── rag
│   ├── mips
│   └── website
├── blog
│   ├── ai
│   ├── cs
│   └── thoughts
├── resume
│   └── resume.pdf
└── contact
    └── links.md
```

验收标准：

- `tree` 能展示完整站点结构。
- `ls`、`cd`、`cat` 的行为符合基本终端直觉。
- 重要内容都能通过 2 到 3 次命令访问到。

### 2.5 桌面背景底座：让可拖动窗口有“可停留的空间”

这是桌面背景线的 P0，只解决基础空间感，不急着做图标、开始菜单或多窗口。

建议：

- 背景保持低对比度深色桌面，窗口仍是视觉焦点。
- 使用一个可互动的轻量屏保主题：缓慢漂浮的节点与连线、极淡网格，或稀疏字符流三选一。
- 鼠标经过时只产生局部、短暂的响应，例如微光、粒子偏移或连线轻微避让。
- 拖动窗口时背景继续自然运行，但不被拖动手势误触发。
- 尊重系统“减少动态效果”设置；移动端降级为静态纹理或关闭粒子。

不建议在此阶段制作大面积 Matrix 字符雨、强闪烁扫描线或高密度粒子。背景的职责是托住窗口，而不是抢走注意力。

验收标准：

- 窗口拖到任意位置后，页面仍有完整、稳定的空间感。
- 背景互动不会遮挡文字、抢占输入焦点或影响拖动窗口。
- 在普通笔记本和移动端上保持流畅，关闭动画后仍然好看。

## 3. P1 互动与探索：让用户愿意继续玩

P1 的目标是把网站从“有风格”升级为“可探索”。

### 3.1 `tree` 做成探索入口

`tree` 不只是展示目录，而是引导用户发现内容。

建议：

- 默认 `tree` 展示主要目录。
- `tree projects` 展示项目列表。
- `tree -a` 或 `ls -la` 展示隐藏文件。

隐藏内容示例：

```text
.secret
.birthday
.matrix
```

验收标准：

- 用户可以通过 `tree` 理解网站全貌。
- 隐藏内容不会影响正常访问路径。
- 探索感来自内容设计，而不是复杂机制。

### 3.2 隐藏文件与彩蛋内容

建议加入少量隐藏文件，让网站有“发现奖励”。

示例：

```bash
cat .secret
```

返回：

```text
You found something that was not listed in the docs.
```

可以设计的隐藏内容：

- `.secret`：一句有趣的个人宣言。
- `.birthday`：生日或个人纪念日彩蛋。
- `.matrix`：短动画或绿色字符雨。
- `.note`：给认真探索者的一句话。

验收标准：

- 彩蛋数量少而精。
- 不影响主要信息获取。
- 彩蛋内容能体现你的个人气质。

### 3.3 有趣但克制的命令

建议优先加入 3 到 5 个轻量命令。

推荐命令：

```bash
coffee
sudo hire yuan
whoami
history
fortune
```

示例：

```text
$ coffee

Coffee initialized.
Productivity +10
```

```text
$ sudo hire yuan

[sudo] password for recruiter:
Checking credentials...
Access granted.

Yuan is open to meaningful opportunities.
Try: cat /contact/links.md
```

验收标准：

- 每个趣味命令都有明确反馈。
- 不出现太多无意义命令。
- 彩蛋最终能自然引导到项目、简历或联系方式。

### 3.4 命令自动补全与历史记录

如果当前命令系统已经比较稳定，可以加入基础键盘体验。

建议：

- 上下方向键切换历史命令。
- `Tab` 自动补全命令或路径。
- 输入错误时给出相近命令提示。

验收标准：

- 常用命令输入更顺手。
- 错误命令不会让用户卡住。
- 移动端不强依赖这些能力。

### 3.5 桌面快捷图标：用图标引导，而非复制内容

当背景底座稳定后，可加入 4 到 6 个桌面图标作为“给不想输入命令的访问者的入口”。

推荐第一批图标：

```text
About       Projects       Blog
Resume      Contact        Readme.txt
```

交互规则：

- 桌面端单击只选中图标，双击打开；移动端单击直接打开。
- “打开”只做三件事：将终端窗口置顶、定位到对应目录、输出下一步可执行命令。
- `Readme.txt` 可以作为新手提示或站点世界观入口；不要再复制一份个人简历。
- 图标位置可采用固定网格或有限范围内的自由摆放；首版不保存用户拖动结果。
- 图标应有键盘焦点、可见选中状态和文字标签，不能只靠图形表达含义。

验收标准：

- 不输入命令的用户也能通过图标找到核心内容。
- 每个图标与一个终端目录或命令有唯一映射。
- 图标交互不产生第二套项目页、博客页或简历页。

## 4. P2 打磨与高级体验：提升质感，但不要重构系统

P2 是体验增强层。等 P0、P1 稳定后再做。

### 4.1 终端视觉打磨

建议增强：

- 顶部栏模拟 macOS / Linux 终端窗口。
- 字体使用适合代码阅读的等宽字体。
- 背景加入极淡网格、噪点或扫描线。
- 光标闪烁。
- 输出有轻微打字或淡入动画。

不建议：

- 大面积霓虹渐变。
- 强烈 CRT 扭曲。
- 影响阅读的闪烁效果。

验收标准：

- 页面更有质感，但文字仍然易读。
- 动画不会影响性能。
- 移动端不会因为视觉效果变得拥挤。

### 4.2 项目详情页增强

每个项目建议统一展示结构：

```text
Name
Summary
Tech Stack
Highlights
Links
Status
```

可以让：

```bash
cat /projects/agent/readme.md
```

展示完整项目介绍。

验收标准：

- 每个项目的信息结构一致。
- 重点突出技术栈、亮点和链接。
- 不只是项目名列表，而是能体现能力。

### 4.3 博客入口增强

博客不一定要一开始做完整系统，可以先做成终端目录。

建议：

- `ls /blog` 展示分类。
- `ls /blog/ai` 展示文章标题。
- `cat /blog/ai/xxx.md` 展示摘要。
- `open /blog/ai/xxx.md` 跳转真实文章页面。

验收标准：

- 博客内容可以被终端发现。
- 不需要一开始实现完整 CMS。
- 未来可以自然接入静态博客生成器。

### 4.4 音效与设置开关

可以加入轻微输入音效，但必须默认关闭或可关闭。

建议命令：

```bash
sound on
sound off
theme dark
theme light
```

验收标准：

- 音效不打扰用户。
- 设置状态能保存到本地。
- 没有声音时网站仍然完整可用。

### 4.5 桌面增强：开始菜单与单窗口状态反馈

开始菜单适合放在桌面背景线的 P2，前提是它被定义为“快速启动器”，不是假装完整系统设置。

推荐菜单结构：

```text
YUAN27.top
──────────
Explore  → About / Projects / Blog
Profile  → Neofetch / Resume / Contact
Settings → Motion / Sound / Theme
Actions  → Reset Desktop / Focus Terminal
```

建议：

- 菜单项仍然调用终端定位或已有设置，不维护独立页面逻辑。
- 可以增加一个简单任务栏：开始按钮、当前终端窗口状态、时钟或一句状态文本。
- “Focus Terminal” 将窗口带回默认位置并聚焦输入框；“Reset Desktop” 仅重置窗口位置与本地视觉设置。
- 若加入最小化，最小化后只显示桌面与任务栏；恢复时回到原窗口和原命令输出。

验收标准：

- 开始菜单不超过两层，不包含冗长设置页。
- 所有菜单操作都能清楚回到或影响终端窗口。
- 只有一个终端窗口时，不制作窗口层叠、分屏、多任务栏等复杂机制。

## 5. P3 可选实验：有趣，但现在不急

P3 可以作为后续版本探索，不建议当前优先投入。

### 5.1 任务系统

让访问者完成简单探索任务，例如：

```text
Quest: Find the hidden contact file.
Progress: 1/3
```

风险：

- 容易把个人网站做得过重。
- 需要更仔细设计任务节奏。

建议：

- 等基础内容稳定后再做。
- 任务数量控制在 3 个以内。

### 5.2 访客留言或命令回放

可以做访客留言、匿名命令记录、最近访问者输入过什么等功能。

风险：

- 涉及存储、审核、防垃圾信息。
- 会显著增加后端和运维复杂度。

建议：

- 当前阶段不做。
- 如果要做，优先接入现成表单或第三方评论系统。

### 5.3 AI 助手模式

例如输入：

```bash
ask yuan "What project should I read first?"
```

风险：

- 需要后端接口和调用成本。
- 容易偏离个人网站核心。
- 回答质量需要控制。

建议：

- 暂时不做实时 AI。
- 可以先做固定问答命令，例如 `faq`。

### 5.4 多主题系统

例如：

```bash
theme matrix
theme light
theme classic
```

风险：

- 设计和测试成本增加。
- 容易让视觉风格变散。

建议：

- 先保留一个主主题。
- 后续最多加一个 light mode。

### 5.5 桌面背景的后续实验

可在 P0 到 P2 成熟后，从下面方向中最多挑选一个试验：

- **情境化屏保**：根据时间切换晨昏色温，或在空闲一段时间后切到低干扰动画。
- **桌面小组件**：仅展示本地时间、站点在线状态、当前目录等一到两个信息，不接入实时外部数据。
- **可发现的桌面彩蛋**：点击隐藏角落或特定图标组合，触发一次短动画，再引导回终端里的隐藏文件。

这些功能都不应依赖后端，不应收集访客行为，也不应成为核心内容的唯一入口。

## 6. 推荐实现顺序

### 第一阶段：完整可用

1. 重构 `help` 命令。
2. 整理 Virtual File System 目录结构。
3. 实现 `tree`。
4. 实现 `neofetch`。
5. 检查移动端基础可用性。
6. 为可拖动窗口建立桌面背景底座，并完成“减少动态效果”的降级策略。

目标：

让网站即使没有彩蛋，也已经是一个完整、有风格、能展示个人信息的终端网站。

### 第二阶段：探索感

1. 加入 `ls -la` 或 `tree -a`。
2. 加入 2 到 3 个隐藏文件。
3. 加入 `coffee`、`whoami`、`sudo hire yuan`。
4. 为错误命令增加提示。
5. 优化命令输出文案。
6. 加入第一批桌面快捷图标，并将每个图标映射到唯一终端入口。

目标：

让访问者愿意主动输入命令，而不是只看一眼就离开。

### 第三阶段：质感提升

1. 打磨终端窗口视觉。
2. 加入光标、输出动画、轻微背景纹理。
3. 统一项目详情展示格式。
4. 增强博客目录浏览。
5. 加入命令历史和 Tab 补全。
6. 加入简洁开始菜单、终端聚焦和桌面重置；评估是否需要单窗口最小化。

目标：

让网站从“有意思”变成“完成度高”。

### 第四阶段：谨慎实验

1. 评估是否需要任务系统。
2. 评估是否需要访客留言。
3. 评估是否需要 AI 问答。
4. 评估是否需要桌面背景实验。
5. 只选择一个方向做小版本验证。

目标：

避免过早把网站复杂化。

## 7. 验收清单

### 7.1 信息展示

- [ ] 用户能在 10 秒内知道这是 YUAN27 的个人网站。
- [ ] 用户能通过 `neofetch` 理解你的身份、方向和关键词。
- [ ] 用户能通过 `tree` 找到 about、projects、blog、resume、contact。
- [ ] 用户能在 3 次命令以内找到联系方式。
- [ ] 项目介绍能体现技术能力，而不只是链接集合。

### 7.2 交互体验

- [ ] `help` 能清楚引导新用户。
- [ ] `ls`、`cd`、`cat`、`tree` 行为符合直觉。
- [ ] 输入错误命令时有友好提示。
- [ ] 彩蛋命令不会干扰正常浏览。
- [ ] 移动端也能完成基础探索。
- [ ] 桌面图标只唤起终端内容，不复制窗口内的信息架构。
- [ ] 拖动窗口、点击背景和输入命令之间不会争夺焦点。

### 7.3 视觉与性能

- [ ] 首屏加载速度稳定。
- [ ] 动画不影响阅读。
- [ ] 终端文字对比度足够。
- [ ] 背景效果不喧宾夺主。
- [ ] 在桌面端和移动端都没有明显排版错乱。
- [ ] 背景互动在低性能设备和“减少动态效果”模式下有合适降级。
- [ ] 窗口始终比背景和图标更容易被注意到。

### 7.4 可维护性

- [ ] 新增目录和文件不需要改大量逻辑。
- [ ] 命令系统有清晰注册方式。
- [ ] 文案内容和命令逻辑尽量分离。
- [ ] 隐藏内容可以单独维护。
- [ ] 后续添加项目或文章成本低。
- [ ] 桌面图标、开始菜单与终端命令共用同一份入口映射配置。

## 8. 现阶段不建议做的功能

### 8.1 不建议做完整登录系统

原因：

- 与个人展示站目标不匹配。
- 增加安全和维护成本。
- 对访问者价值不高。

### 8.2 不建议做复杂后台管理

原因：

- 当前内容规模还不需要。
- 静态数据或配置文件更简单。
- 过早后台化会拖慢迭代。

### 8.3 不建议做实时多人互动

原因：

- 技术复杂度高。
- 需要处理滥用和稳定性问题。
- 对当前个人站核心目标帮助有限。

### 8.4 不建议一开始接入真实 AI 聊天

原因：

- 成本和质量都需要控制。
- 网站核心是展示你，而不是让 AI 抢掉主角。
- 可以先用固定命令和 FAQ 替代。

### 8.5 不建议过度游戏化

原因：

- 个人网站首先要让别人了解你。
- 如果隐藏太深，招聘者或访问者可能找不到关键信息。
- 彩蛋应该是奖励，不应该成为门槛。

### 8.6 不建议现在做完整的网页操作系统

包括多窗口管理、文件拖拽、可编辑桌面、模拟进程、复杂通知中心或仿真设置面板。

原因：

- 当前只有一个主终端窗口，完整窗口管理没有实际价值。
- 模拟复杂操作系统会显著增加状态同步、移动端适配和无障碍成本。
- 用户真正想看的仍然是你的内容与项目；桌面感应该服务于它们。

### 8.7 不建议让屏保背景承载关键信息

原因：

- 动画背景天然不利于稳定阅读和检索。
- 对减少动态效果、移动端和低性能设备不友好。
- 它会模糊“窗口内负责内容、窗口外负责氛围”的边界。

## 10. 总结

YUAN27.top 当前最适合走的方向不是“功能更多”，而是“更像一个完整、有个性、可探索的小系统”。

优先级应该是：

1. 先完成终端体验闭环。
2. 再增加探索和彩蛋。
3. 然后打磨视觉和输入体验。
4. 再让桌面背景提供轻量导航与状态反馈。
5. 最后谨慎尝试更复杂的实验功能。

窗口内始终是内容与探索主线；桌面背景始终是氛围与快捷入口。只要 P0 和 P1 做好，这个网站就已经会比普通个人主页更有记忆点；P2 决定完成度，P3 则只适合在基础稳定后少量尝试。
